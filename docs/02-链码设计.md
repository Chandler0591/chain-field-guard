# 链码设计(agrichain)

> 实现:Go + fabric-contract-api-go v1.2.2,部署于 `agri-channel`。源码与测试见 [chaincode/agrichain/](../../chaincode/agrichain/)。

## 1. 批次状态机

```
                 AnchorData                 CounterSign
        INIT ────────────────► ANCHORED ─────────────────► COUNTER_SIGNED
        (未上链)   (录入人)      (已锚定)      (核对人验签)        │  ▲
                                   │                             │  │ 批准/拒绝
                    RecordAICheck  │   (AI 预检存证,不改状态)     │  │
                                   ▼                             ▼  │
                               AI 结论哈希上链                  PENDING ─┘
                                            ApproveModification(审核人)

                 FinalizeBatch(审核人)
        COUNTER_SIGNED ─────────────────────────► FINALIZED
                                                   (锁定,颁发凭证,拒绝一切写入)
```

> AI 预检(`RecordAICheck`)插入在锚定之后、核对签名之前:链下 AI 分析结论哈希上链存证,
> **不改变状态机** —— AI 只辅助决策,核对人签名前可查看风险提示,是否签名仍由人工决定。

## 2. 函数签名表

| 函数 | 允许角色 | 前置状态 | 后置状态 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `AnchorData(batchId, dataCid, sha256)` | operator | 批次不存在 | ANCHORED | 写入 v1(ACTIVE),链上只存 CID+哈希 |
| `RecordAICheck(batchId, reportCid, reportHash, riskScore, flags, modelVersion)` | operator | ANCHORED 且未预检 | 不变 | AI 预检结论存证(见 §7),每批次仅一次 |
| `CounterSign(batchId, signature, clientTimestamp)` | checker | ANCHORED | COUNTER_SIGNED | 链上验签(见 §5),签名记录 |
| `RequestModification(batchId, newCid, newSha256, reason)` | operator/checker | COUNTER_SIGNED 且无待审核请求 | PENDING | 登记请求,不改历史版本 |
| `ApproveModification(batchId, approved)` | auditor | PENDING | COUNTER_SIGNED | 批准:追加新版本、旧版本 DEPRECATED;拒绝:请求作废 |
| `FinalizeBatch(batchId)` | auditor | COUNTER_SIGNED | FINALIZED | 生成凭证 ID `VC-<batchId>-<txId>` |
| `GetBatch(batchId)` | 任意(含监管) | — | — | 批次详情 |
| `GetAllVersions(batchId)` | 任意(含监管) | — | — | 全版本历史(含 DEPRECATED) |
| `VerifyBatch(batchId, sha256)` | 任意(含监管) | — | — | 哈希比对,返回 MATCH/MISMATCH |
| `GetCredential(batchId)` | 任意(含监管) | FINALIZED | — | 查询数字凭证 ID |

## 3. 链上数据结构

```
ProductBatch {
  batchId            批次号(状态键)
  status             状态机当前状态
  versions[]         全部版本(追加式,永不覆盖)
  currentVersion     当前生效版本号
  signatures[]       核对人签名(hex)
  pendingModification 待审核修改请求(nil 表示无)
  credentialId       数字凭证 ID(锁定后生成)
  aiCheck            AI 预检存证(nil 表示未预检)
}

BatchVersion { version, cid, sha256, anchoredBy, anchoredAt, status(ACTIVE/DEPRECATED) }
PendingModification { newCid, newSha256, reason, requestedBy }
AICheck { reportCid, reportHash, riskScore, riskLevel, flags[], modelVersion, checkedBy, checkedAt }
```

## 4. 权限模型(双重防线)

1. **组织级**:所有写函数入口先调用 `rejectRegulatorWrite` —— 调用者 MSPID 为 `Org2MSP`(监管方)时一律拒绝,监管只读不受角色属性影响。
2. **角色级**:`requireRole` / `requireAnyRole` 通过 `ClientIdentity.AssertAttributeValue("role", ...)` 断言调用者证书中的 role 属性(operator/checker/auditor),属性由 Fabric CA 注册身份时签发(`--id.attrs '"role=<角色>:ecert"'`),链码读取证书而非交易参数,无法伪造。

## 5. 链上验签约定(CounterSign)

签名数据包(前后端约定一致,**不可随意改动**):

```
payload = batchId + "|" + 当前版本CID + "|" + 客户端签名时间戳(Unix 秒)
```

- 后端(核对人)签名时取本机 Unix 秒作为 clientTimestamp,与签名一起随交易上链;
- 链码校验 `|clientTimestamp - stub.GetTxTimestamp().Seconds| ≤ 600s`(容差),
  既避免客户端无法预知链上交易时间的跨秒问题,又防止旧签名重放;
- 后端用 node:crypto 的 ECDSA P-256 私钥对 payload 做 SHA-256 后签名(ASN.1 DER),
  hex 编码随交易上链;
- 链码用调用者证书公钥(ecdsa.VerifyASN1)验签:
  验签通过才推进状态,保证"核对人真实核对过该版本数据且不可抵赖"。

## 6. 修改语义(追加式,不覆盖)

- 批准修改 = `versions` 数组追加新版本(currentVersion+1,ACTIVE),旧版本全部标记 DEPRECATED,**内容保留**;
- 任何写操作都不覆盖历史字段,审计查询走 `GetAllVersions` 而非单个覆盖值。

## 7. AI 预检设计(链下智能 + 链上存证 + 人工决策)

| 层次 | 内容 | 位置 |
| :--- | :--- | :--- |
| 链下智能 | 可插拔引擎(provider 模式)分析结构化检测数据(产地/产品类型/农残/铅/水分/菌落总数/亚硝酸盐),输出风险评分 0-100、异常项与各维度得分明细 | 后端 services/ai.js |
| 链下留档 | 完整分析报告(输入快照/阈值/结论/引擎/模型版本/明细)存 IPFS | IPFS |
| 链上存证 | 报告 CID + SHA-256 + 摘要(评分/等级/异常项/模型版本)由 RecordAICheck 写入 | 链码 |
| 人工决策 | 结论不改变状态机;核对人签名前查看风险提示(含各维度明细),自行决定继续签名或发起修改 | 前端核对签名页 |

### 7.1 链下引擎可插拔(provider 模式)

后端 AI 引擎按 `AI_PROVIDER` 切换,链码完全无感知(链上只存摘要):

```
AI_PROVIDER=rule(默认)           AI_PROVIDER=http
  ┌──────────────────┐            ┌──────────────────────────┐
  │ RuleEngineProvider│            │ HttpModelProvider         │
  │ 阈值规则引擎(离线) │            │ POST AI_MODEL_URL 模型服务 │
  └──────────────────┘            └───────────┬──────────────┘
                                              │ 超时/非 2xx/响应非法
                                              ▼
                                自动降级回退 RuleEngineProvider,
                                报告 modelVersion 标注「降级:模型服务不可用」
```

- 规则引擎阈值:农残 0.01/0.1、铅 0.1/0.2、亚硝酸盐 2/20 mg/kg,菌落总数 1e6/1e7 CFU/g(警示 30 分/严重 60 分),水分超 5%~20% 记 20 分,总分封顶 100;
- 模型服务约定返回 `{ riskScore, flags, details, modelVersion }`,版本号随存证上链,历史存证可区分"哪个模型做的判断";
- 演示用 mock 模型服务:`node scripts/mock-ai-model.js`(零依赖,3100 端口),配合 `AI_PROVIDER=http` 即可演示"真实模型接入 + 失败降级"。

- **风险等级由链码从评分派生**(`riskLevelOf`:0-29 NORMAL / 30-59 WARN / 60-100 HIGH),链上以分值为唯一权威,避免前后端口径不一致;
- 每批次仅允许一次预检(结论是证据,不允许覆盖);
- 得分明细(details)不进链,只在 IPFS 报告与 API 响应中返回(链上只存摘要,数据瘦身);
- 监管追溯:监管方凭 reportCid 从 IPFS 取回报告原文,重算 SHA-256 与链上 reportHash 比对(后端 ai-check 查询接口的 verified 字段),即可核实"AI 在什么时间(checkedAt)、基于什么数据(输入快照)、用什么模型(modelVersion)、做出什么判断(评分/异常项/明细)"。

```bash
cd network
./network.sh deployCC -ccn agrichain -ccp ../chaincode/agrichain -ccl go
```

部署脚本会执行 `go mod vendor` 并打包,需要 Go 1.22+ 与可用 GOPROXY。
