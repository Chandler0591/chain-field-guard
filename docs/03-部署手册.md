# 部署手册 —— 从零部署到演示

> 本文档覆盖:环境准备 → 启动网络 → 部署链码 → 启动后端/前端 → 测试 → 端到端演示 → 压测(可选)→ 区块链浏览器(可选)→ 常见问题。
> 每一步都给出**期望结果**,跑挂任何一步都可以按编号对照排查(见文末"常见问题")。
> 环境搭建细节(代理/工具链)见 [docs/01-环境搭建.md](01-环境搭建.md)。

## 0. 总体架构速览

```
浏览器(Vue3 前端)
    │ /api(代理)
后端(Express + fabric-gateway + kubo-rpc-client)
    ├─ gRPC ──► Fabric 网络(Docker 容器:peer0.org1 / peer0.org2 / orderer + CA)
    │             └─ agri-channel 上的 agrichain 链码(Go,批次状态机)
    └─ HTTP ──► IPFS Kubo 容器(文件本体,链上只存 CID + SHA-256)
```

角色与组织(见 [network/README.md](../network/README.md)):

| 角色 | 组织 | 权限 |
| :--- | :--- | :--- |
| operator 录入人 | Org1 | AnchorData、RequestModification |
| checker 核对人 | Org1 | CounterSign、RequestModification |
| auditor 审核人 | Org1 | ApproveModification、FinalizeBatch |
| regulator 监管 | Org2 | 仅查询(链码内拒绝一切写) |

## 1. 环境准备(一次性)

按 [docs/01-环境搭建.md](01-环境搭建.md) 完成:

- Docker Desktop(WSL 集成)+ 镜像代理;
- WSL2 内:git、Node.js 22+、Go 1.22+;
- Fabric 2.5 二进制与镜像可用官方一键脚本拉取(约 2GB,走代理):

```bash
curl -sSLO https://raw.githubusercontent.com/hyperledger/fabric/main/scripts/install-fabric.sh
chmod +x install-fabric.sh
./install-fabric.sh --fabric-version 2.5.11 docker binary
```

> 本项目自带 `network/`(官方 test-network),无需 fabric-samples 即可启动;拉 fabric-samples 只是为了验证环境(01 文档第 5~6 节)。

**验收**:`~/fabric-samples/test-network/network.sh up` 能成功,`docker ps` 能看到 peer/orderer 容器。

## 3. 启动网络 + 注册角色身份(约 2 分钟)

> **推荐一键部署**:仓库根目录执行 `./scripts/envctl.sh deploy`,
> 自动完成第 3~8 节全部步骤(网络 + 链码 + IPFS + 钱包 + 依赖 + 启动前后端),
> 链码 sequence 自动检测递增。以下分步命令供手动操作或排障参考。

```bash
cd network
./network.sh up createChannel -ca
```

**期望结果**:

1. `docker ps` 出现 5 个容器:`peer0.org1.example.com`、`peer0.org2.example.com`、`orderer.example.com`、`ca_org1`、`ca_org2`(另有 ca_orderer);
2. 日志末尾:`Channel 'agri-channel' joined`;
3. 角色身份目录已生成(可抽查证书中的 role 属性):

```bash
ls organizations/peerOrganizations/org1.example.com/users/
# 期望包含: Operator@org1.example.com  Checker@org1.example.com  Auditor@org1.example.com
ls organizations/peerOrganizations/org2.example.com/users/
# 期望包含: Regulator@org2.example.com

# 抽查 role 属性已写入证书(期望输出含 role=operator)
openssl x509 -in organizations/peerOrganizations/org1.example.com/users/Operator@org1.example.com/msp/signcerts/cert.pem -noout -text | grep -A1 role
```

## 4. 部署链码(约 2 分钟)

```bash
cd network
./network.sh deployCC -ccn agrichain -ccp ../chaincode/agrichain/cmd -ccl go
```

**期望结果**:日志末尾输出 `Committed chaincode definition on channel 'agri-channel'`。

> deployCC 内部执行 `go mod vendor` 后自动构建链码镜像并部署到两个 peer,无需手动打包。
> 链码代码更新后需递增 sequence 重新部署(全新环境默认 1);
> 用 `./scripts/envctl.sh deploy` 可自动查询已提交 sequence 并递增,无需手动指定。

## 6. 启动 IPFS

```bash

```

## 8. 前端:启动与演示

```bash
cd ../frontend
npm install
npm run dev
```

浏览器打开 **http://localhost:5173**,按 [frontend/README.md](../frontend/README.md) 第 4 节的十步剧本演示:

1. **录入人**:「上传锚定」页上传检验文件、填批次号 → 状态 ANCHORED;
2. **录入人**:「AI 预检」页录入结构化检测数据(产地/农残/铅/水分,可选填菌落总数/亚硝酸盐)→ 链下分析 → 结论哈希上链 + 各维度得分明细表(如农残 0.03 → WARN「农药残留超标」,状态不变);
3. **录入人(可选 HIGH 场景)**:农残填 0.15 → HIGH 60 分「疑似高农药残留」→ 核对页红色告警强烈建议人工复核;
4. **核对人**:「核对签名」页查询批次 → 看到 AI 风险提示(含各维度明细与模型版本)后人工复核:
   - 确认合格 → 点"从 IPFS 取回文件核对" → 核对签名 → COUNTER_SIGNED;
   - 认定不合格 → 填驳回原因 → 核对驳回 → REJECTED(原因链上留痕);
5. **录入人(驳回整改,可选)**:「修改复核」页左侧显示驳回历史 → 上传整改版文件、填整改说明 → 整改重提 → ANCHORED(v2 追加、v1 归档)→ 重新 AI 预检(旧结论归档)→ 回到步骤 4 重新核对;
6. **录入人**:「修改复核」页左侧上传修订版文件、填原因 → 提交 → PENDING;
7. **审核人**:「修改复核」页右侧查看请求 → 批准 → 状态回 COUNTER_SIGNED,v2 追加、v1 标 DEPRECATED;
8. **审核人**:「锁定与凭证」页锁定 → FINALIZED,展示凭证 ID 与二维码;
9. **消费者**:「消费者验证」页输批次号 + 选文件 → MATCH(换错误文件 → MISMATCH;未签发批次会明确提示不可验证);
10. **监管方**:「监管审计」页查询 → 全部版本完整可见(追加式、不覆盖);「AI 预检」页可查看存证并核验报告哈希。

## 8.1 日常启停与清理(envctl.sh)

部署完成后,日常开关机/重启用 [scripts/envctl.sh](../scripts/envctl.sh) 一键管理:

```bash
./scripts/envctl.sh status    # 查看容器/端口/健康状态
./scripts/envctl.sh stop      # 停止全部组件(Fabric/IPFS 容器保留,账本数据不丢)
./scripts/envctl.sh start     # 恢复启动(关机后容器 Exited 属正常,start 即可恢复)
./scripts/envctl.sh restart   # 重启
./scripts/envctl.sh clean     # 彻底清理:拆除网络/容器/卷/证书/钱包(需交互确认,或加 -y)
./scripts/envctl.sh deploy    # 清理后重新一键部署(sequence 自动递增)
```

> 日常停用请用 `stop` 而非 `clean`;`clean` 会删除账本数据,执行后需重新 `deploy`。

## 10. 压测(可选)

```bash
./scripts/load-test.sh 20   # 连续锚定 20 个批次
```

**期望结果**:输出"总耗时 Xs · 平均吞吐 X 批次/秒"(含 IPFS 上传耗时,纯链上写吞吐更高)。

> 与通用溯源模板常用的 tape 压测工具的区别:tape 直连 peer 提交提案,测的是纯链码背书吞吐;load-test.sh 走完整 HTTP 链路(上传 IPFS → 路由 → 网关提交),更贴近真实业务。演示用 load-test.sh 即可,进阶可自行引入 tape(hyperledger/fabric-test 仓库)。

## 11. 常见问题排查

| 现象 | 原因与处理 |
| :--- | :--- |
| `network.sh up` 卡在拉镜像 | Docker 镜像代理未生效:核对 Docker Desktop → Settings → Proxies 与 01 文档第 2 节 |
| 排序节点报 `system-channel ... requires unsupported orderer` 类错误 | Docker 镜像版本过旧(1.4.x 等):`docker images \| grep hyperledger` 核对应为 2.5.x,按 01 文档用 `install-fabric.sh --fabric-version 2.5.11` 重新拉取 |
| 网络启动/交易报错但不知原因 | 先看节点日志:`docker logs -f orderer.example.com`(排序)、`docker logs -f peer0.org1.example.com`(背书),报错链路清晰可见 |
| 链码部署报 `go mod vendor` 失败 | GOPROXY 不通:WSL 内设置 `go env -w GOPROXY=https://goproxy.cn,direct` |
| `/api/health` 返回 503 | 网络未启动 / 链码未部署 / 钱包未初始化:依次核对第 3、4、7 步 |
| 写接口报"权限不足" | 请求角色与接口白名单不匹配:核对 backend/README.md 第 3 节角色表 |
| 核对签名报"验签失败" | 签名数据包与链码约定不一致:确认未改动 signer.js 与 access.go 的拼接规则 |
| AI 预检报 502 / 报告核验不一致 | Kubo 容器未启动或报告被篡改:核对第 6 步与 backend/.env 的 IPFS_API_URL;核验不一致时检查报告 CID 指向的文件是否被替换 |
| 上传报 502 | Kubo 容器未启动或 IPFS_API_URL 错误:核对第 6 步与 backend/.env |
| 前端页面报"无法连接后端" | 后端未启动或端口非 3000:按 frontend/README.md 第 2 节用 BACKEND_URL 指定 |
| 重建环境 | 依次:`network.sh down` → 删除 `network/organizations` → 重新执行第 3~4 步;后端钱包重跑 `npm run setup-wallet` |

## 12. 区块链浏览器(可选)

借鉴"Fabric 2.5 通用溯源模板"的做法,可加装 Hyperledger Explorer 可视化区块与交易,演示时打开浏览器看"区块高度随操作增长"非常直观:

```bash
git clone https://github.com/hyperledger-labs/blockchain-explorer.git ~/blockchain-explorer
cd ~/blockchain-explorer
```

配置要点(官方 `examples/net1` 正是为 test-network 设计,本项目 `network/` 即官方 test-network,组织名与端口完全一致,可直接参考):

1. 连接配置 `examples/net1/connection-profile/test-network.json`:把证书路径指向本项目 `network/organizations/peerOrganizations/...` 下的 MSP 与 TLS 证书;
2. `examples/net1/docker-compose.yaml`:把密钥材料挂载路径改为上述绝对路径;
3. 启动:`cd examples/net1 && docker compose up -d`,浏览器打开 http://localhost:8080(默认账号 admin / adminpw)。

**期望结果**:仪表盘出现 peer0.org1 / peer0.org2 与 agri-channel;每提交一笔交易区块高度 +1;按交易 ID 可查每次 AnchorData / AI 预检 / 签名操作的详情。

> Explorer 仅用于展示,不参与业务读写;装不上不影响任何功能,可跳过。
